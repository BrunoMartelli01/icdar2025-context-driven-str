# CLIP verification of PARSeq transcriptions

**Approximate reproduction**, Total-Text TRAIN125 already used for development,
not independent TEST or reproduced Table 5.
Protocol: [configuration](../configs/approximate/clip_word_verification_train_v1.json).

## Place in the project

The reference work uses AG-UNet/ResNet-50, mask components, original-image crops,
and PARSeq-S. It compares readings with a BLIP-2 description through MPNet and
lexical similarity, falling back to DeepSolo when scores are insufficient.
Local PDF sections3.3–3.5 and Algorithms1/2 are the source; unresolved details
remain in `PAPER_AMBIGUITIES.md` and `STRICT_REPRODUCTION_STATUS.md`.

The repository now includes a PARSeq runtime and many approximate experiments,
as well as the historical scaffold described in the README. The adapter strictly
loads an official checkpoint with provenance; its paper PARSeq-S mapping remains
unresolved. This experiment reuses existing readings without changing
segmentation, PARSeq, DeepSolo, or STRICT scoring.

## Existing CLIP implementations

`scripts/crop_clip_runtime.py` and `recognition/crop_clip_battery.py` compare each
crop variant with its reading. Scores change with two variables: pixels and
word. Earlier CLIP selection deteriorated substantially with padding. Its
documentation reports374/983 for threshold-only CLIP margin 0.02, versus 368/983
baseline and 403/983 PARSeq control; selected boxes could change.

`recognition/group_word_selection_runtime.py` already addresses this by sharing
the reference image among competing words. The new module extends comparison
with descriptions, controls, and correct/incorrect-reading discrimination.
**New results have fixed boxes** and are not interchangeable with old-battery numbers.

## Literature ideas

* [Original CLIP, §3.1.4 and appendix E.2](https://arxiv.org/pdf/2103.00020):
  evaluates OCR, observing domain and repeated-digit/character sensitivity.
  Quoted OCR prompts help; embedding-space ensembles are also described.
  This motivates written-word prompts/mean embeddings without guaranteeing
  Total-Text outcomes.
* [CLIPTER, ICCV 2023](https://arxiv.org/abs/2301.07464v2): combines whole-scene
  and recognizer features through gated attention, requiring fine-tuning.
  Separating global context/local evidence is transferable; simple cosine
  reranking here is not CLIPTER.
* [CLIP4STR](https://arxiv.org/html/2305.14014v4): visual/multimodal branches
  with trained recognition decoders, followed by prediction/refinement. A
  specialized-verifier direction, not proof that generic frozen CLIP can correct
  every word.
* [Disentangling visual and written concepts in CLIP, CVPR 2022](https://joaanna.github.io/disentangling_spelling_in_clip/):
  studies visual-concept/spelling separation, including meaningless words and
  learned projections. This motivates distinguishing letter recognition from
  semantic plausibility; a trained projection is a different experiment from
  this training-free verifier.

## Controlled comparison

Inputs: the original 1.173 anchors of the TRAIN125 battery. Alternatives are only
**raw** PARSeq strings from zero-padding threshold variants. Repeated words keep
all source IDs and maximum available PARSeq confidence. No GT/dictionary/
captioner words are added. Original baseline always remains in the pool. Final
box always stays at threshold 0.5/zero padding, regardless of the winning word.

Each candidate sees four images shared within its anchor:

1. complete original image;
2. original baseline crop;
3. crop with doubled width/height, clipped to image boundaries;
4. identical wide crop with the word rectangle covered by its median color.

A median-color square canvas retains the whole field of view before the official
processor. The fourth input controls surrounding context; it is not a new
localization proposal, and synthetic covering may introduce artifacts.

Compared prompts: raw word, quoted written word, three-template ensemble, word
plus description, contextual residual, and description cyclically swapped from
the next image in the complete population. Context prompt:

```text
a photo of the written word "WORD". Scene: DESCRIPTION
```

Word precedes description. Above77 tokens, only the common description prefix
is shortened; the word is never truncated. Budget, actual prefix, and prompts
are saved per image. Descriptions were already generated by
**Florence-2-large-ft** on the same SHA256-verified originals. They are not
BLIP-2 and may contain their own text hypotheses, explicitly detected by the audit.

The residual is the experimental hypothesis
`normalize(embedding(word + caption) - embedding(prompt without word + caption))`.
Subtracting only the caption score, identical across alternatives, **would not
change ranking**. Normalizing the feature difference may change it; benefit
must be measured, not assumed.

Compare free CLIP selection, PARSeq confidence, equal-weight PARSeq/CLIP-crop-
ensemble midrank fusion, and conservative agreement: change only when PARSeq,
crop, and wide crop agree, with crop cosine gain strictly above0.02. Ties keep
baseline. No value was optimized on this battery's outcomes.

## Metrics and limitations

Main metric: exact words after Unicode casefold, punctuation retained,
deterministic one-to-one bbox matching at IoU >=0.5. All care GT remain in the
denominator, including unpredicted words; empty strings never match. Annotations
open only after all selections are saved. Reports retain GT/prediction IDs,
gains, harms, changes, and a fixed-box pool oracle.

Correctness AUROC uses baseline boxes overlapping exactly one care GT, separately
counting missing/ambiguous associations and missing scores. Its PARSeq confidence
is **original baseline** confidence; alternative ranking instead uses maximum
available per-word confidence. Also measure whether correct words beat wrong
pool alternatives, separating Levenshtein-distance-one pairs. Pairs/anchors are
correlated, not independent samples supporting significance claims.

Cosine, margin, and restricted-pool softmax are not calibrated correctness
probabilities. No new DeepSolo routing threshold is introduced. Selecting the
best arm on these 125 images is exploratory; a frozen rule and independent
verification are required.

## Repeat and compare checkpoints

The runner installs no dependencies and downloads no models. Inputs/paths are
in the [local profile](../configs/approximate/clip_word_verification_local_paths_v1.json).
Checkpoint directories must be named by full commit. The runner saves file
checksums, checks B/32, B/16, or L/14 architecture, and rejects missing/unexpected/
mismatched keys. No model fallback is performed.

```bash
.venvs/context-str-main-py311/bin/python -m pytest -q \
  tests/recognition/test_clip_word_verifier.py \
  tests/recognition/test_totaltext_crop_clip_battery.py \
  tests/recognition/test_group_word_selection.py

.venvs/context-str-main-py311/bin/python -u -m scripts.run_clip_word_verification \
  --model vit_b32 --device cpu
```

Add `--limit 1` for real smoke. Explicit GPU selection is `--device cuda:0`:
CUDA unavailability fails and records the error without changing device.
Float32, batch 16, four CPU threads, deterministic seed/settings, and separately
loaded models are recorded as `HARDWARE_DEVIATION`. CUDA allocated/reserved
peaks are measured; CPU values are `null`, without invented VRAM measurements.
OOM is recorded/propagated; a simulated-error test does not qualify hardware.

To complete comparison on a networked host, download both official snapshots
using the existing environment client into the local profile's paths. No

Complete B/32 CPU finished all 125 images,1173 anchors,983 care GT. **Fixed-box**
available-word ceiling is405/983. Alternatives come from 4878 threshold-only
crops; templates/rules were fixed before scoring. All28 arms are in JSON.

| Rule, identical final boxes | Correct /983 | Gained | Lost | Changed words |
| --- | ---: | ---: | ---: | ---: |
| PARSeq baseline |368|0|0|0|
| PARSeq confidence over alternatives |383|26|11|351|
| CLIP whole image, raw word |344|15|39|411|
| CLIP crop, raw word |353|15|30|375|
| CLIP crop, quoted written word |362|14|20|363|
| CLIP crop, ensemble |361|13|20|365|
| CLIP crop, word+description |355|14|27|368|
| CLIP crop, swapped description |359|13|22|358|
| CLIP crop, normalized contextual residual |369|19|18|370|
| CLIP wide crop, ensemble |360|21|29|393|

**Direct description addition does not help the crop in this test**:355 versus
362 for the description-free template, even below swapped-description359.
Whole-image contextual prompt355 is near written-template353, both below
baseline368. Contextual residual recovers19/loses18: net+1 is exploratory,
not reliable-benefit evidence. Wide masked control347 suggests surrounding-
context plausibility alone is insufficient; covering also introduces synthetic
visual alteration.

The conservative gate recovers `RumCo.` → `Rum` (`total_text:464`) and
`DECAIDIES` → `DECADES` (`total_text:989`). Seven other changes add no exact
words; no observed harm guarantees nothing on other data. PARSeq confidence
alone gives more overall recoveries; CLIP fusion378 is still below control383.
This run therefore does not justify CLIP as the default corrector.

Wrong-reading identification is weaker with CLIP too. On482 anchors with one
GT association,365 correct baselines and 117 incorrect:

| Evidence | Correct/incorrect AUROC | Comparisons won, all 160 pairs |67 one-edit pairs |
| --- | ---: | ---: | ---: |
| PARSeq confidence |0.823|81.9%|82.1%|
| CLIP raw crop |0.580|57.5%|56.7%|
| CLIP written crop |0.615|66.9%|59.7%|
| CLIP crop ensemble |0.622|66.9%|59.7%|
| CLIP crop with description |0.562|60.6%|53.7%|

| CLIP wide-crop ensemble |0.645|65.0%|70.1%|

There are also688 anchors without care-GT overlap and 3 ambiguous associations,
excluded only from conditional AUROC and retained in main metrics. Descriptions
literally mention160 of 482 associated targets and are not pure text-free
semantics. For mentioned targets, description-free crop template gives134/160
correct versus contextual129/160; without mention,225/322 versus 223/322.
This split is post-hoc, not a new GT-selected rule.

The practical direction, subject to further validation, is CLIP as **secondary
evidence with abstention from change**, subordinate to visual/PARSeq support.
Future B/16/L/14 comparison must retain identical pools/boxes; later calibration
and independent verification can establish a gate. Smaller B/16/L/14 patches
provide more visual positions at224 pixels: motivation to test characters, not
an improvement guarantee. CLIPTER/CLIP4STR/spelling projections indicate learned-
adaptation directions. Pretrained weights/projections could be used frozen
without local training, but must be qualified as distinct components; local
fine-tuning would change the training-free constraint. The
[official projection code](https://github.com/joaanna/disentangling_spelling_in_clip)
points to pretrained artifacts and normalized feature projection. Availability,
provenance, and compatibility with local B/32 remain unverified; this battery
did not evaluate them.
