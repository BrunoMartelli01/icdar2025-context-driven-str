## Motivation and authoritative sources

The local reference paper `papers/2503.15639v2.pdf`, sections 3.3–3.5, describes
context scoring and fallback recognition; it does not specify a BERT spelling
postprocessor. This user-requested extension is isolated from STRICT configs.
The earlier generic MLM experiments remain recorded in
`docs/TOTALTEXT_BERT_CORRECTION.md`: baseline384, MLM word_only381/local_ocr383;
relaxing its PARSeq confidence-protection gate produced341/363. These TRAIN
diagnostics motivate a separately evaluated spelling-trained head; they do not
establish that it will improve scene OCR.

[NeuSpell: A Neural Spelling Correction Toolkit](https://aclanthology.org/2020.emnlp-demos.21/)
provides the spelling-correction inspiration. The selected English checkpoint
is [murali1996/bert-base-cased-spell-correction](https://huggingface.co/murali1996/bert-base-cased-spell-correction),
revision `d2a5bbccc41a0f4ff5e7c16e1c3b8d96ba8883b2`.
Its label head has100002 classes and hidden width768. Domain transfer from
English spelling errors to scene OCR, rare names and other languages remains
an `ASSUMPTION`; positive aggregate transfer is not established by the measured
v2 protocol.

The [author's inference snippet](https://github.com/neuspell/neuspell/blob/aa3782c2ea25d286b487ead3d99389dfc6801907/scripts/huggingface/huggingface-snippet-for-neuspell.py)
is the authoritative decoding reference (`REPOSITORY_SPECIFIED`): retain the
noisy word in BERT input, average its final subword states, apply the genuine
trained classifier, map argmax through the external word vocabulary.
This is neither an MLM nor a newly initialized correction head. The legacy
checkpoint config's `architectures: [BertModel]` does not replace that trained
classifier; every required backbone/classifier tensor must load strictly.

## Frozen inputs and correction protocol

Current config: `configs/approximate/totaltext_letterbox_neuspell_correction_v2.json`.
The initial v1 config and its failed host output remain as historical evidence.
Source remains the latest completed letterbox `word_f1_control`, with the same
source/checkpoint/PARSeq hashes used in the preceding BERT experiments. Input
is512x512, native mask256x256, external contours mapped back to original RGB,
padding0 and no area/top10 filtering. Reusing this existing path is
`REPOSITORY_SPECIFIED`, rather than strict Algorithm1 reproduction.

All125 frozen TRAIN-holdout images,949 proposals and983 care words are retained.
Preparation reproduces384 exact casefold /372 case-sensitive /475 fuzzy
one-to-one matches; geometric IoU>=0.5 matches remain503. It verifies source
protocol/report, masks, image/crop identities, PARSeq outputs and checkpoints.
GT enters `evaluation_labels.json`, separately from observable `inputs.json`;
inference opens neither GT nor the baseline file.

The following policies are explicitly `ASSUMPTION`:

- Score only ASCII single words of length>=3 with lowercase, uppercase or title
  casing. Preserve punctuation, numeric, internal mixed-case and multiword
  outputs. On these inputs,555 of949 crops are eligible. NeuSpell receives the
  original word, not a masked replacement. No native PARSeq confidence gate is
  applied; high native confidence is not a calibrated correctness estimate.
- `word_only` and `local_ocr` change only BERT context. Local context uses up to
  three original OCR neighbours per side, vertical overlap>=0.5 and horizontal
  gap<=8 word heights. Neighbour text is frozen, never recursively corrected.
  Fast-tokenizer offsets select the target subwords; their mean pooling is
  checked against a separate reference calculation.
- Optional `--captions FILE` adds `local_ocr_caption` with at most80 whitespace
  words as a scene prefix in the same BERT segment. Captions require a pinned
  model revision, weight hashes, decoding settings and exact125-image coverage
  bound to sample IDs and RGB hashes. Existing ICDAR13 captions cannot be used.
  NeuSpell was not qualified for caption-prefix conditioning, so this is a
  separate experimental condition. No Total-Text captions were generated in
  this milestone.
- Do not silently truncate over256 tokens or score an unknown/special target
  subword. Emit a recorded KEEP abstention. Neural errors, nonfinite logits and
  OOM propagate and are logged as failed experiments.

Two selection arms share the same neural inference:

| Arm | Selection |
| --- | --- |
| `native_head` | Author-style argmax on eligible words, first class index on ties. Special predicted labels pass through the original word. Other head casing is retained. |
| `conservative` | KEEP unless the predicted ASCII word passes the edit/probability checks below. Preserve original casing when a correction is accepted. |

Conservative edit limits: at most1 edit for source lengths3–5,2 for length>=6;
Levenshtein/max(source length,candidate length)<=0.3; predicted label
probability>=0.5. A same-casefold prediction keeps the original string.
When the original exists in the head vocabulary, sum actual probabilities
across its casefold-equivalent labels and require
`log P(predicted label) - log P(KEEP aliases) > 1.5` (KEEP on equality).
An OOV original has no scoreable class: use only the stated edit/probability
gate and record the reference probability as null. The UNK class is never
treated as the probability of that arbitrary original string. These thresholds
are fixed hypotheses, not calibrated or selected on TEST data.

## Evaluation, runtime and artifacts

Micro exact Unicode casefold matches retain punctuation, use axis-aligned
bboxIoU>=0.5 deterministic maximum one-to-one matching and denominator983,
including unmatched GT. Also report case-sensitive and RapidFuzz>=80 matches,
recovered/damaged GT indices, changed crops and explicit abstentions per image.
No failed samples are dropped. Geometry and crop identity must remain fixed;
the exact delta must equal recovered minus damaged. This inherited diagnostic

`HARDWARE_DEVIATION`: explicit CPU or single CUDA:0, batch8, max256 tokens,
four CPU threads, seed20261006, deterministic algorithms and TF32 disabled.
Model set/device/precision/batch/shapes, software, loading audit, timing and
allocated/reserved GPU peaks are saved. CPU GPU-memory fields are null. No GPU
execution or 8GB memory qualification has yet been performed. Selection arms
reuse the same inference timing; reported time is correction-only, not the
segmentation/PARSeq/caption end-to-end runtime.

Stages: `prepare` -> `fetch-model` -> `infer` -> `evaluate`. Outputs contain
fully resolved config and implementation hashes, `inputs.json`, separate
`evaluation_labels.json`/`baseline.json`, `runtime.json`, per-image/condition
inference shards and `results.json`. Sealed files are idempotent and conflicting
changes require a new output directory/version. Resume verifies shards and
recomputes selections. Weight/vocabulary caches belong outside git.
